# StartApp

Десктопная карта проекта с редактором на **C11 и GTK4**. Первая версия рассчитана
на изучение небольших и средних проектов C/C++: открыть папку, увидеть файлы
и локальные `#include`, исправить исходник и обновить карту после сохранения.

## Возможности текущей версии

- Выбор папки через диалог или аргумент командной строки.
- Асинхронное сканирование, дерево каталогов и паспорт проекта.
- Поиск по имени и относительному пути файла без учёта регистра, с поддержкой
  Unicode и сохранением родительских каталогов в результатах.
- Обнаружение `Makefile`, `CMakeLists.txt`, `*.cmake`, `*.mk`, `meson.build`,
  `build.ninja`; эти файлы доступны в редакторе.
- Редактор UTF-8: простая подсветка C, undo/redo, сохранение, перечитывание файла.
- Номера строк с синхронной прокруткой и выделением текущей строки; ширина
  поля подстраивается под число строк.
- Граф локальных включений: стрелка ведёт от исходного файла к заголовку.
  Доступны обзор проекта и ближайшие связи выбранного файла.
- Нажатие на узел открывает файл. Сохранение обновляет анализ и граф.
- Источник связи виден в панели под графом: путь, номер строки, имя включения.
- Нажатие на ссылку `файл:строка` открывает источник, выделяет строку `#include`
  и прокручивает редактор к ней. Для заголовка показаны также входящие связи.
- Отдельные состояния для системных, неразрешённых и неоднозначных включений.
- Импорт `compile_commands.json`: пути `-I`, `-iquote`, `-isystem`, `/I`, `/external:I`
  и контекст исходника для вложенных заголовков.
- CMake File API: граф целей, их типы, исходники, артефакты и ссылки на строки
  определения и зависимости. Выбор каталога сборки и конфигурации Debug/Release.
- Тёмная серо-чёрная тема с оранжевыми акцентами, кнопки без видимых рамок,
  подсветка наведения/активации и системное управление окном.
- Подтверждение сохранения при переключении файла, проекта и закрытии окна.
- Атомарная запись через GIO; внешние изменения не перезаписываются молча.
- JSON-анализ без графического дисплея: `--inspect`.

## Сборка и запуск

**Linux и Windows 10/11 x64:** пошаговая сборка, установка и переносимый ZIP
описаны в [docs/PLATFORMS.md](docs/PLATFORMS.md). CMake-сборка:

```sh
cmake -S . -B build/linux -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build/linux --parallel 2
```

На Windows используйте MSYS2 UCRT64 и `bash scripts/build-windows.sh`.
Для запуска готовой Windows-папки достаточно `startapp.exe`; MSYS2 не требуется.

Нужны C-компилятор, pkg-config, **GTK4 >= 4.12** и **JSON-GLib >= 1.6**,
CMake/Ninja либо GNU Make.
Проверенная платформа — Debian 13, GTK 4.18.6. Приложение не использует C++,
Python, LLM или сетевые сервисы.

На Debian 13 / Ubuntu 24.04:

```sh
sudo apt-get update
sudo apt-get install build-essential pkg-config libgtk-4-dev libjson-glib-dev
make -j2
./build/startapp /путь/к/проекту
```

Без аргумента приложение открывает пустое окно с кнопкой выбора проекта.
`make run` открывает текущий репозиторий. Для обычного запуска нужен рабочий
графический сеанс Linux (X11 или Wayland).

В подготовленной облачной среде зависимости находятся вне репозитория:

```sh
cd /workspace/StartApp
. /workspace/.startapp-env/activate.sh
make -j2
./build/startapp --inspect .
make test
make test-ui
```

Для воспроизведения установки в Debian 13 без административных прав:

```sh
sh scripts/setup-cloud.sh
. /workspace/.startapp-env/activate.sh
```

Скрипт скачивает проверенные APT пакеты и распаковывает их в
`/workspace/.startapp-env/root`; системные файлы и настройки APT не меняет.
Доступ к сети нужен только для установки зависимостей.

## Работа с редактором

1. Откройте папку проекта и выберите файл в дереве или на графе.
2. Внесите изменение. Точка рядом с именем означает несохранённые правки.
3. Сохраните: карта пересчитается по файлам на диске.
4. При конфликте внешних изменений сохранение будет отклонено. Скопируйте
   нужные правки, затем нажмите «Перечитать» для загрузки актуального файла.

Горячие клавиши: **Ctrl+O** — проект, **Ctrl+S** — сохранить,
**Ctrl+P** — поиск файлов, **Ctrl+R** — пересканировать,
**Ctrl+Z / Ctrl+Shift+Z** — undo/redo в редакторе.
«Обновить карту» читает данные с диска, не изменяя текущий буфер редактора;
несохранённые изменения в граф не попадают.

Поиск фильтрует дерево по подстроке относительного пути: `api.h` находит файл
в любом каталоге, `src/api` уточняет расположение. **Enter** открывает первый
файл результата, **Esc** очищает запрос и возвращает фокус редактору.
Если совпадений нет, открытый документ и его правки остаются доступны.
При открытии другого проекта запрос сбрасывается.

Ссылки происхождения используют номера строк сохранённой версии. Если текущий
файл изменён в редакторе, сначала сохраните его: переход по ссылке в тот же файл
предложит это в строке состояния. Переход в другой файл использует обычный
диалог сохранения; после подтверждения открывается именно запрошенная строка.
При внешнем изменении исходников перечитайте файл и обновите карту.

Для графа сборки нажмите **«Цели»**. Выбор цели в списке или на карте показывает
её зависимости; ссылка `CMakeLists.txt:строка` открывает место определения.
**«Каталог сборки…»** выбирает папку с готовыми метаданными, переключатель
конфигурации позволяет отдельно изучить Debug или Release. Как подготовить
метаданные на Linux и Windows: [docs/BUILD_METADATA.md](docs/BUILD_METADATA.md).

Палитра: фон `#181818`, панели `#202020`, текст `#ece9e4`, приглушённый текст
`#aaa6a0`, акцент `#e79873`. Клавиатурный фокус остаётся заметным. Приложение
не создаёт своих кнопок закрытия/сворачивания/разворачивания: их предоставляет
Windows или оконный менеджер Linux. На Wayland вид рамки зависит от композитора
и стандартного оформления GTK. Разделители панелей можно перетаскивать;
граф меняет раскладку при сужении панели, а большие списки прокручиваются.

## Границы анализа

Это первая версия редактора и навигатора, а не законченная универсальная IDE.
Цели импортируются из готового CMake File API, другие найденные файлы сборки
пока доступны для просмотра и правки без разбора их целей.
Приложение никогда не выполняет команды из открытого проекта автоматически.

Анализ `#include` статический и приблизительный. При наличии метаданных
используются пути поиска конкретного исходника; они передаются вложенным
заголовкам. Без метаданных проверяется путь относительно исходника, затем
корень проекта и уникальное совпадение по окончанию пути — эта эвристика
явно отмечается в панели связей и JSON. Условия препроцессора, макросы,
продолжения директив через `\\`, встроенные пути компилятора и response-файлы
не вычисляются. Включения внутри неактивных `#if` также отображаются.
Неоднозначность не разрешается произвольным выбором файла. Системные
заголовки не сканируются за пределами проекта.

Символические ссылки не обходятся. `.git`, `build`, `dist`, `node_modules`,
`target`, виртуальные окружения и `cmake-build-*` пропускаются.
Произвольные правила `.gitignore` пока не интерпретируются.
Обрабатываются известные текстовые форматы, до 10 000 файлов и 64 уровней
вложенности; предел размера редактируемого файла — 2 MiB. Пропуски и ошибки
чтения отражаются в паспорте и JSON.
Обзор показывает до 60 узлов, окрестность — до 20 входящих и 20 исходящих
соседей. Остальные файлы доступны в дереве, цели — в списке; полный граф — в JSON.
Единообразные окончания строк LF/CRLF сохраняются; смешанные нормализуются в LF.
Запись отслеживает внешние изменения, но не предназначена для защиты от
враждебной одновременной подмены файловой системы.

## Проверки

```sh
make test
make test-ui
./build/startapp --inspect . > build/project.json
```

`make test` выполняет тесты ядра: разрешение и неоднозначность включений,
комментарии и номера строк, исключения, пустой проект, Unicode, сохранение
и пересканирование, права файла, конфликт внешних изменений, CRLF,
отклонение бинарных файлов и подмена файла символической ссылкой; поиск
по имени и пути, Unicode-нормализация, пустой запрос и отсутствие совпадений.
Дополнительно проверяются команды Windows, порядок поиска заголовков,
вложенные включения и циклы, разные контексты общего заголовка, повреждённый
JSON, защита от обхода путей reply, конфигурации CMake и каталоги с русскими
символами/пробелами. CMake-тест `metadata-self` импортирует настоящий результат
конфигурации собственного проекта и проверяет цели и связи библиотек.

Для GUI-теста без дисплея нужны `xvfb`, `xauth`, `dbus-daemon`:

```sh
sudo apt-get install xvfb xauth dbus-daemon
make test-ui
```

GUI-тест создаёт и удаляет собственный временный проект. Он проверяет загрузку,
редактирование, сохранение, обновление графа, переход по узлу, undo/redo,
отмену переключения и сохранение через диалог. Дополнительно проверяются
поиск, Enter/Esc, русские имена, сохранение правок при фильтрации, переход
по ссылке к строке 101, сохранение перед переходом, прокрутка номеров строк
и отрисовка последней пустой строки. Затем проверяются импорт метаданных,
навигация по целям и строкам CMake, переключение Debug/Release без потери
буфера, системная рамка и размещение кнопок после изменения размера окна.
Скриншот текущего запуска
сохраняется в `build/smoke-ui.png`.
Для CMake он находится в каталоге сборки. CI также проверяет обе платформы
и запуск распакованного Windows ZIP без MSYS2 в PATH.

## Устройство проекта и следующие этапы

- `src/project.c` — сканирование, анализ и JSON; не зависит от интерфейса GTK.
- `src/document.c` — загрузка и сохранение; не зависит от интерфейса GTK.
- `src/build_metadata.c` — безопасное чтение JSON, команды компилятора и CMake File API.
- `src/graph.c` — отрисовка Cairo/Pango и навигация по графу.
- `src/editor.c` — поле номеров строк и переход к строке источника.
- `src/app.c` — GTK4 интерфейс и управление состоянием.
- `src/theme.c` — единая палитра GTK, редактора и графа.
- `src/main.c` — запуск интерфейса и консольного анализа.

План развития, до пяти этапов:

1. **Готово:** работающий цикл «папка → карта → правка → обновление».
2. **Готово:** поиск файлов, номера строк, переход к строке происхождения связи.
3. **Готово:** импорт `compile_commands.json` и метаданных CMake File API для более точных
   связей и графа целей сборки.
4. **Следующий:** явный запуск выбранной команды сборки с диагностикой; интеграция clangd.
5. Изменение поддерживаемых зависимостей через граф с предварительным diff.
