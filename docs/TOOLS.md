# Инструменты StartApp 0.6

Откройте проект и нажмите **Инструменты**. Окно читает собственный снимок файлов,
не заимствуя модель редактора. Операции анализа идут в фоне; «Остановить задачу»
отменяет чтение, а при внешней команде завершает её дерево процессов.
Перед сменой проекта/закрытием приложения текущую задачу нужно завершить.

## Редактор и восстановление

**＋** закрепляет текущий документ во вкладке (до 20). Между закреплёнными
документами сохраняются текст, курсор и независимая история отмены. Обычный
не закреплённый документ остаётся предварительным просмотром с диалогом
сохранения при переключении. «Закрыть вкладку» закрывает активную закреплённую
вкладку. Закрытие проекта/приложения и сборка проверяют также неактивные вкладки.
Состав вкладок между запусками пока не восстанавливается; последний файл —
через обычный сеанс, несохранённый текст — через черновики при открытии файла.

Через 1,5 секунды после изменения черновики записываются в фоне, атомарно,
в пользовательский `startapp/recovery` рядом с `workspace.ini`. Исходники не
перезаписываются. Восстановление при открытии возможно только если SHA-256
исходной дисковой версии совпадает; иначе показывается путь отдельного черновика
для ручного сравнения. Сохранение или явный отказ от правок удаляют черновик.
Сбой до завершения фоновой записи может потерять последние изменения.

Внешние изменения отслеживаются в корне и до 256 каталогах индексируемых файлов,
а также в каталоге сборки и CMake reply. Чистый текущий документ перечитывается;
изменённый буфер сохраняется, запись проверяет конфликт. Чистые закреплённые
вкладки проверяются при повторном открытии. Файлы в ненаблюдаемых/пустых вложенных
каталогах можно перечитать через «Обновить карту». Сканирование отменяется
кнопкой × рядом с обновлением; неизменившиеся включения повторно не разбираются,
но их разрешение и метаданные пересчитываются.

## Clangd

Установите clangd, при необходимости укажите путь через кнопку настроек рядом
с переключателем **clangd**. Включение разрешает запуск сервера. Требуется C/C++
файл; для точных ответов выберите каталог с `compile_commands.json`.

- **F12** — определение символа, включая переход внутри несохранённого файла.
- **Ctrl+Space / Дополнить** — список вариантов; выбор применяет замену текста.
- **Проверить** — диагностика текущего буфера; после правок она обновляется
  с задержкой 800 мс. Подчёркивания и подсказка редактора показывают сообщения.

Сервер получает UTF-8 текст, позиции преобразуются в UTF-16 по LSP. Устаревшие
ответы после изменения текста/файла пропускаются. Запрос ограничен 15 секундами,
сообщение — 8 MiB, список дополнений — 100 вариантами. Snippet-дополнения не
применяются; дополнительные правки других мест/файлов и массовые refactoring
операции пока не поддерживаются. Диагностика относится к активному буферу;
несохранённые неактивные заголовки сервер не получает. Clangd config/background
index/clang-tidy отключены; команды базы компиляции редактором не запускаются.

## Карта и анализ

Поле фильтра ищет файл/цель по имени и пути. В локальном режиме можно выбрать
зависимости, пользователей или оба направления; глубина **0** означает все
уровни. «Весь проект» показывает обзор. Нажатие на ребро выводит происхождение
и ссылку на строку. В свёрнутой группе показывается представитель связи;
для изучения отдельных связей раскройте группу. Отдельная проверка архитектуры
рассматривает весь индекс, независимо от ограничения карты в 200 узлов.

Во вкладке **Последствия изменений** укажите относительный путь: результат
содержит прямых/косвенных пользователей и цели с затронутыми исходниками.
Это потенциальные последствия статических `#include`, включая неактивные `#if`.
Нажатие на результат поиска/анализа открывает соответствующую строку редактора.
Поиск текста ищет буквальную подстроку без учёта регистра в сохранённых UTF-8
файлах, до 2000 результатов. Несохранённые буферы в поиск не входят.

Архитектурные правила задаются в редакторе вкладки и могут храниться в
`.startapp-rules.ini` проекта:

```ini
[UI must not depend directly on platform]
from=src/ui/*
to=src/platform/*
```

Каждая секция запрещает включения `from → to`; пути относительные, `*` и `?`
обозначают шаблоны. До 128 правил, 500 сообщений о нарушениях. Также показываются
обратные связи DFS, доказывающие наличие циклов, до 100 строк; это не перечисление
всех возможных циклических путей. Проверка ничего не исправляет автоматически.

**Сравнение конфигураций**: A — метаданные текущего проекта, B — указанные каталог
и конфигурация. Сравниваются наборы файлов, цели/артефакты/исходники, связи,
пути заголовков и доступные команды/фрагменты компиляции, включая `-D` и `-U`.
Вывод — до 2000 изменений; изменившиеся абсолютные пути также считаются отличием.
Конфигурации должны быть подготовлены; сравнение не запускает CMake.

## Каталог, Git и окружение

Карточки хранятся в пользовательском `startapp/catalog.ini`: до 100 локальных
проектов, путь, сводка, сборка и последний файл. Поиск фильтрует карточки;
нажатие проходит через обычную защиту несохранённых правок.

Git запускается кнопками: статус, diff, список изменений ревизий и сравнение
графа одного коммита с рабочими файлами. Статус отмечает изменённые файлы точкой
в дереве/карте; отметки обновляются новым запросом статуса. Индекс и коммиты
не изменяются, external diff/textconv отключены.

Для графа используется `git archive` во временный собственный каталог, затем
извлекается ограниченное подмножество обычных файлов: tar до 64 MiB, до 10 000
файлов по 2 MiB. Символические ссылки не создаются, обход путей отклоняется.
Исторические сборочные скрипты не запускаются. Сравнивается статическая структура
включений и простые цели Make; историческая конфигурация CMake не восстанавливается.
Для этой операции задайте один коммит, например `HEAD~1`, а не диапазон.

**Окружение** проверяет наличие инструментов в PATH, доступность путей компиляторов
и каталогов заголовков. Версии компиляторов отображаются из метаданных. Это
первичная диагностика; совместимость SDK/библиотек и версии установленного
инструмента проверяются его конфигурацией и сборкой.

## Конфигурация, сборка, запуск и отладка

Во вкладке конфигурации выберите CMake/Meson/Make, путь инструмента, каталог и
цель. CMake поддерживает генератор, тип и configure-пресет; пресет задаёт генератор
и конфигурацию, поле каталога переопределяет `binaryDir`. Создаются File API queries
и включается compile database. Meson использует `setup`, затем `compile`; для
повторного setup уже существующей сборки может потребоваться внешний `meson
setup --reconfigure`. Make не имеет общего этапа конфигурации, выполняется
непосредственно выбранная цель корневого Makefile. Параллелизм — два задания.

Meson цели/артефакты/исходники читаются из `meson-info/intro-targets.json`, пути
заголовков — из compile database. Межцелевые связи Meson по именам библиотек
не угадываются. Make — приближение: одна простая буквальная цель на строку,
зависимости между распознанными целями, без вычисления переменных/шаблонов/include.

В окне инструментов действия работают с дисковыми файлами. Сохраните нужные
правки перед конфигурацией/сборкой; отдельная основная кнопка сборки показывает
диалог сохранения. После конфигурации обновляются метаданные основного окна.

**Запуск и отладка** используют исполняемую цель CMake/Meson с существующим
артефактом. Задайте аргументы (POSIX-кавычки, без shell) и рабочий каталог.
Вывод поступает в журнал. Ввод с клавиатуры в запущенную программу не подключён.

Отладчик GDB или LLDB запускается в batch-режиме: точка останова по функции
или `файл:строка`, запуск, стеки всех потоков и локальные переменные, завершение.
Интерактивное пошаговое управление пока не реализовано. Нужна сборка с отладочной
информацией. Автозагрузка пользовательских init-файлов отключена; для GDB также
ограничена автозагрузка project scripts. Остановка завершает дерево процесса
через process group Linux или Job Object Windows.

## Экспорт и проверки

Экспорт сохраняет SVG или самостоятельный HTML с поиском и выделением соседей,
до 200 первых узлов. Длинные подписи видны в tooltip. Полная модель остаётся
доступной через `--inspect`; графические экспорты могут иметь пересечения рёбер.

`make test` и CTest проверяют поиск, транзитивные связи, правила/циклы, экспорт,
каталог, конфликты черновиков, отмену/инкрементальное сканирование, Make/Meson,
UTF-16 и настоящий clangd. Workflow-тесты создают собственные проекты и проверяют
CMake Debug/Release, запуск с аргументами, GDB, Meson, Make и Git archive.
Отсутствующие необязательные инструменты дают явный skip соответствующего теста;
CI устанавливает их. Portable GUI тестируется с PATH без MSYS2 и не требует их.
GUI проверяет также вкладки/undo, сохранение во время остановленной сборки,
фильтры графа и все страницы анализа инструментов.
